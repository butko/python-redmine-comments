## 1. Название и назначение

- Название: redmine_commenter
- Назначение (1–2 предложения): добавляет комментарий к одной задаче Redmine через браузер, когда REST API и приём почты недоступны.
- Пользователь результата: владелец учётной записи Redmine с обычными правами.

## 2. Стек и среда

- Язык и версия: Python 3.10+
- Внешние библиотеки: Selenium 4.x (единственная внешняя зависимость)
- Платформа запуска: Astra Linux
- Целевой браузер: Chromium (установлен в системе, `/usr/bin/chromium`). Альтернативы — Google Chrome, Яндекс.Браузер.
- Ограничения целевой среды: графическая сессия (X11/Wayland). Системный Python защищён PEP 668. Требуется драйвер, мажорная версия которого совпадает с версией браузера.
- Способ установки зависимостей: `venv`. Команды — в `readme.md`.

## 4. Команды запуска

- Обычный запуск: `python3 redmine_commenter.py` (`--config config.ini` — только для нестандартного имени или пути)
- Одноразовый вход в Redmine: `python3 redmine_commenter.py --login`

## 5. Правила, специфические для проекта

- **Режим `auto` (по умолчанию).** Логика:
  1. Порт 9222 отвечает как Chrome DevTools → attach.
  2. Иначе → launch выделенного экземпляра с `profile_dir` и флагом `--remote-debugging-port=9222`.
- **Выделенный профиль.** `profile_dir = ./browser_profile` в папке скрипта. Не конфликтует с профилем основного браузера.
- **`--login` и отсоединение процесса.** При одноразовом входе браузер запускается через `subprocess.Popen(..., start_new_session=True)`. Процесс не получает SIGHUP при завершении скрипта.
- **Поиск драйвера в папке скрипта.** Порядок: `chromedriver` → `yandexdriver`. Оба имени принимаются без переименования. Если в папке ничего нет — используется `driver_path` из конфига, затем Selenium Manager.
- **Совместимость драйвера и браузера.** Мажорная версия драйвера должна совпадать с версией браузера. Для Chromium и ChromeDriver это всегда выполнимо.
- **Структура страницы задачи Redmine.** Поле `#issue_notes` находится внутри скрытого блока `#update` (`style="display:none"`). Форма открывается через `showAndScrollTo('update', 'issue_notes')` или принудительной установкой `display`. На странице может быть несколько кнопок с `name="commit"`; submit-кнопка ищется строго внутри `#issue-form`. Подтверждение результата — появление текста в `#history`.
- **Текст комментария: `comment_file` или `comment_text`.** Приоритет — `comment_file`, если он непустой; иначе `comment_text`. Файл читается в UTF-8, относительный путь считается от папки скрипта. Для многострочного текста с пустыми строками, списками и markdown-разметкой используется только файл: в INI пустые строки и произвольная разметка сохраняются ненадёжно. Символ `\n` в `comment_text` не разворачивается в перевод строки.
- **Один запуск — один комментарий** к одной задаче (`issue_url`).
- **Обезличивание**: в примерах — `example.com`, `your_login`.
- **Лицензия**: CC BY-SA 4.0 (по умолчанию, см. 6.14 в rules-common.md). Отклонений нет.

## 6. Специфика документации проекта

- **Документация обновляется сразу, а не по запросу.** При любом изменении кода, конфига, структуры или поведения программы `readme.md`, `rules-project.md` и (при необходимости) `scheme.svg` обновляются в том же ответе, в котором вносится изменение. Отдельного запроса пользователя не требуется. Это уточнение к правилу 6.12: проверка актуальности выполняется не «при завершении этапа», а при каждом изменении, затрагивающем эксплуатационные аспекты или структуру. Версии файлов поднимаются по 10.6.
- **Раздел «История изменений» в `readme.md`** ведётся отдельным файлом, не заводится (см. ниже); записи добавляются в обратном хронологическом порядке, каждая — с указанием версии и сути изменения.

## 7. Ограничения проекта

- Подключиться к **уже запущенному браузеру без `--remote-debugging-port`** невозможно — фундаментальное ограничение Chrome/Chromium. Решается выделенным профилем.
- Селекторы Redmine могут меняться при обновлении или смене темы. Скрипт рассчитан на стандартную тему (`theme-Classic`); для кастомных тем селекторы `#update`, `#issue-form`, `#issue_notes`, `#history` могут потребовать правки.
- Не поддерживаются 2FA/SSO, требующие интерактивной проверки на каждом запуске.
- Для режима `launch` (и `auto`, когда порт не слушается) на первом запуске нужен `--login`.
- Драйвер и браузер должны иметь совпадающие мажорные версии.
- `browser_profile/` содержит cookie-сессию — не публиковать.
